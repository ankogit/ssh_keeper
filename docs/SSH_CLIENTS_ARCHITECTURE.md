# SSH-сессия

Подключение открывает системный `ssh` в настоящем терминале. Bubble Tea на это время отпускает alt-screen (`tea.ExecProcess`) и забирает его обратно, когда сессия заканчивается. Ресайз, nano и vim обрабатывает сам OpenSSH: процесс `ssh` — foreground на реальном tty и получает `SIGWINCH`.

Сборка команды — `internal/ssh/session.go`. Отдельного PTY в приложении нет.

## Аутентификация

Способ входа задаёт `UseSSHKey`.

- Ключ: `-i <путь>` и `IdentitiesOnly=yes`, если путь указан. Пустой путь оставляет выбор OpenSSH: агент и ключи по умолчанию. Passphrase ключа спрашивает сам `ssh`, приложение её не хранит.
- Пароль сохранён: `SSH_ASKPASS` указывает на бинарник `ssh-keeper`, `SSH_ASKPASS_REQUIRE=force`. Процесс читает пароль из файла `0600` и печатает его, если выставлен `SSH_KEEPER_ASKPASS`. Пароль не попадает в аргументы команды. Файл удаляется после сессии.
- Пароль не сохранён: askpass не используется, OpenSSH спрашивает пароль в том же терминале.

## known_hosts

Системный `~/.ssh/known_hosts` не изменяется. Используется только `~/.ssh-keeper/known_hosts`.

Перед сессией `internal/ssh/hostkey.go` читает ключ сервера и обрывает рукопожатие до логина.

- Ключ совпал — сразу запускается `ssh` с `StrictHostKeyChecking=yes`.
- Хост новый — вопрос «доверять?». Да записывает ключ и подключает.
- Ключ другой — вопрос «перезаписать?». Да удаляет старые строки этого адреса и записывает новый. Так обрабатывается переустановка сервера или смена ключа.
- Сервер недоступен — сессия не запускается, ошибка остаётся в списке.

`GlobalKnownHostsFile` указывает на пустое устройство, чтобы системный `known_hosts` не подмешивался к этой проверке.
